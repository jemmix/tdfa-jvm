# Multi-valued tags — an obscure corner, kept deliberately

Status: **kept for now, still weighed** against a minimal-scope freeze. This
page is the candid accounting: what the feature buys, what it costs, and why
the ledger currently comes out positive. If that flips, dropping it earlier
is cheaper than later — `MULTI_VALUED_TAGS` and `groupSpans` are public API,
and removal after adoption is a breaking change.

## What it is

An opt-in compile lane (`Pattern.MULTI_VALUED_TAGS`, BT22 §3.1) where a
capture group under repetition keeps its whole offset sequence instead of
only the last iteration's span. Default compiles are untouched;
single-value results are bit-identical, `LONGEST_MATCH` composes.

```java
Pattern p = Pattern.compile("(?:(a)|(b))+", Pattern.MULTI_VALUED_TAGS);
PatternMatcher m = p.matcher("abab");
m.find();
m.groupSpans(1);  // [0,1, 2,3]  — g1 in every participating iteration
m.groupSpans(2);  // [1,2, 3,4]
m.start(1);       // 2 — the LAST pair, same as a plain compile
```

The hard-to-replace shape is per-iteration correlation — iteration *k* of
one group aligned with iteration *k* of another:

```java
// " id=42 name=abc ts=9" → pairs of (key, value) spans, one pass
Pattern kv = Pattern.compile("(?:\\s*(\\w+)=([^ ]+))+", Pattern.MULTI_VALUED_TAGS);
```

A `find()` loop over a sub-pattern cannot reliably reconstruct that pairing
when iterations are variable-width, and it cannot validate the enclosing
structure (separator rules, no trailing junk) at all — only the one
automaton can guarantee both.

## Why keep something this obscure

Honest sizing first: capture histories are a minority taste. Across regex
ecosystems the mainstream APIs (`java.util.regex`, PCRE, Python, JS, RE2,
Go, Rust) keep last-iteration only. The evidence that real consumers want
more:

- **.NET shipped it** as `Group.Captures`/`CaptureCollection` in 1.0 and has
  kept it for two decades; "how do I get all captures of a repeated group?"
  is a perennial top-voted question for the engines that lack it.
- **re2c** implements the same feature first-class (`#mtag`, `YYMTAGP`/
  `YYMTAGN`/`YYCOPYMTAG`, worked examples in a dozen languages) and its
  manual recommends the same prefix-tree representation our `TagTree` uses;
  BT22 §3.1 — the paper this library implements — is that feature's
  formalization, co-authored by re2c's maintainer.
- **Verified production use exists**, sparsely: espurna (IoT firmware, IR
  raw-code timing pairs) and Mux's hlstools (HLS playlist attribute lists)
  build directly on re2c m-tags. Power users, not a crowd — but real.

The ledger:

- **For:** the only capability on offer that `java.util.regex` and re2j
  cannot match (a reason to adopt this library rather than swap it in);
  paper conformance for §3.1; demand pockets proven by .NET precedent and
  re2c users; the lane is fenced — opt-in flag, single values asserted
  bit-identical, PikeSim write-log oracle, parity and determinism suites.
- **Against:** ~50 `multi` branch sites threaded through the determinizer
  and both engine tiers — the two highest-complexity components in the
  tree; a second pass-configuration semantics (the lane permanently skips
  fixed-tag, register-renaming and regopt, so artifacts can be larger and a
  near-budget pattern may reject where a plain compile fits); public API
  and an emitted-surface coupling (`TagTree.snapshot()` is linked by name
  from generated bytecode).

Costs are real but lane-local and paid only by opt-in consumers; the
differentiator is library-wide. That is the keep.

## Semantics notes for the curious

- Histories record **participating iterations only** — bypassed iterations
  contribute no entry (the re2j capture contract: a value once set stays).
  re2c's m-tags differ: `YYMTAGN` appends an explicit nil per bypassed
  iteration. Porting re2c m-tag code? Expect one fewer entry per skipped
  repetition here.
- Every match step appends one node per repeated tag — linear, but a
  constant factor over the plain walk; snapshots handed to result holders
  are immutable trimmed copies, so `MatchResult` stays shareable across
  threads.
