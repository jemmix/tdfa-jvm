## 1. Fixed in this round (all verified: full `check` green, quick-bench gate OK)

### B1 — Minimizer merged states on a 32-bit hash (silent-wrong-match risk)

`Tdfa.DfaMinimizer.fillAttrs` folded each 64-cell `stateStopOnAcceptMask` /
`stateFinalOpsByMask` row into a single int and put that hash into the `SigKey`;
a birthday collision (~2⁻³² per pair of distinct rows, real at 10 K+ distinct
rows) made semantically different states compare equal → unsound Moore merge →
silently wrong match lengths. **Fix:** the full rows now go into the signature
(`attrExtra()` = 64 cells per active row); equality is exact by construction.
Tdfa.java `fillAttrs`/`attrSig`/`transSig`.

### B2 — Parser crash-hardening + re2j parity (6 fix families)

All semantics verified empirically against vendored re2j 1.8 before landing
(probe results recorded in `Parser.java` comments):

1. **Repeat-count cap** `{n,m} ≤ 1000` ("invalid repeat count", re2j's exact
   rule): previously `a{500000000}` OOM'd the eager TNFA desugaring before any
   determinization budget could fire; `a{2147483648}` threw raw
   `NumberFormatException`. Overflow-safe `parseRepeatCount`.
2. **Group-nesting depth cap** (1000): `"(".repeat(20000)` previously escaped
   `Pattern.compile` as a raw `StackOverflowError` (re2j parses iteratively;
   we are recursive — cap needed). `MAX_GROUP_DEPTH`.
3. **Group-scoped inline flags**: every `)` now restores the flags saved at its
   `(` (`((?i)a)b` no longer folds `b` — re2j behavior, probe-verified);
   flag-only groups `(?i)` persist into the enclosing group. The old code only
   restored for the `(?flags:` form.
4. **"missing argument to repetition operator"** for `*a`/`(+a)`/`a|*b`/
   `{2}a` (previously silent literal misparse — `*a` *matched* `"*a"`);
   **"invalid nested repetition operator"** for `a**`/`a++`/`a*{2}`/`a{2}{3}`
   (previously `a*{2}` = `a*` + literal `"{2}"`; possessive `a*+` threw a
   non-parity `UnsupportedOperationException`).
5. **ASCII-digit-only braces** (`a{٥}` was silently parsed as `a{5}`; re2j
   treats it as the literal string `"a{٥}"`), **group-name validation**
   (`(?<a b>`/`(?<-b>`/`(?<>` → "invalid named capture"; digit-first allowed,
   matching re2j), **hex-overflow hygiene** (`\x{1100000}` → clean parse error,
   re2j's message; zero-padded `\x{00000061}` still accepted — caught by the
   vendored RE2 ExecTest on first run).

Tests: `ParserHardeningParityTest` (re2j as live oracle, both engine
factories, 40 cases), `ParserHardeningTest` (crash-hygiene pins).

### B3 — ASM fallback net caught `RuntimeException` only

A `VerifyError`/`NoSuchMethodError`/`NoSuchFieldError` from generated bytecode
escaped `Pattern.compile` raw (shell field linkage is lazy — could detonate
mid-match in user code). Both emission fallback sites in `PatternCompiler` now
catch `RuntimeException | LinkageError` and degrade to the interpreter with an
observer note. This is the safety net for every post-thaw emitter bug.

### B4 — Thread-safety contract violations (documented "safe for concurrent
use" vs two racy structures)

1. **`SearchDfa`** (lazy search-DFA memo): mutation path (`internRow` /
   `transition` / `buildBlock`) now confined under a lock; the per-codepoint
   READ path is lock-free through immutable volatile-published snapshots
   (`rowWordsArr`, `rowBlockIdsArr` COW rows, `blocksArr`) with
   length-checked stale-snapshot fallbacks into the locked path. Locking the
   read path itself would have put a monitor enter/exit on every scanned char
   (3–10× trigger-scan regression) — see the class javadoc for the protocol.
   `step()` (dead) removed; `ensureSeed()` is idempotent/race-safe.
2. **`walkBlockIdx`** per-state block-id tables: now an
   `AtomicReferenceArray`; the volatile cell write publishes the fully-built
   −1-filled array, so a racing reader sees `null` (builds its own, benignly
   duplicated) or a fully-initialized array — previously a stale default-0
   cell misread as block id 0 = wrong dispatch on aarch64.
   `buildWalkBlock` double-checks against the published array under the lock.
3. The comment that (falsely) called the memo "ThreadLocal" fixed.

Test: `ConcurrencyHammerTest` — 8 threads, synchronized cold-start, five
exercises (search-DFA trigger, walk blocks on Cyrillic/Greek, anchored,
core-tier findAll, lazy-quantifier trigger); every thread must produce
bit-identical digests to the single-threaded reference.

**Fresh-seed differential fuzz after the parser-semantics changes**

## 1b. Follow-up round (same day): JDK-floor evaluation + Checkstyle/Qodana one-offs

### SpotBugs vs "Java 26" — precise statement

SpotBugs 4.9.x cannot **run on** a JDK 26 JVM: its bundled ASM cannot parse the
JDK 26 runtime's own classes (class file major 70) when it scans referenced
types, and the degraded analysis is worse than none (canary-verified: an
obvious EI_EXPOSE_REP produced "0 findings" + 200 analysis errors). It
**analyzes class files of any target up to major 69 fine** when run on JDK ≤
25. Conclusion: no project downgrade needed — ever — only the *analyzer's*
JVM matters. Do NOT downgrade the build to an old LTS:

- Gradle 9.5 itself requires JDK 17+ to run.
- ErrorProne requires JDK 17+ to run.
- Checkstyle 14.x requires JDK 11+ to run.
- The right model is three independent knobs: **build JVM** (current — 26
  today, or pin 21 LTS for calm), **bytecode target** (see below), **analyzer
  JVM** (whatever each tool needs: SpotBugs ≤ 25, everything else current).

### The Java 8 floor — evaluation

Dream: compile on Java 8 unless things clearly suffer. Evidence gathered:

- **The floor is already nearly met by the ecosystem around us**: the only
  runtime dependency, `org.ow2.asm:asm:9.9.1`, ships **class file major 49
  (Java 5)**; re2j 1.8 — the drop-in charter — ships **major 50 (Java 6)**;
  and our own ASM tier already emits **V1_8 (52)** for generated per-pattern
  classes. A Java 8 floor makes the library installable by every re2j
  consumer, which is the market the charter names.
- **Post-8 surface in library main code is tiny and mechanical** (verified by
  grep, 2026-09-04): 3 records (`ParseResult`, `Generated`, `Spec`), 2
  pattern-matching `instanceof` binds, 4 `var`s, ~10 `List.of`/`Map.of`/
  `copyOf` sites, 1 file with arrow-switch (`Parser`), 0 text blocks, 0
  `String.repeat/isBlank/strip/toList`, 0 `CharSequence.isEmpty()` default-
  method landmines (all `.isEmpty()` uses are on `String`/`List`/`Map`). The
  unicode generator modules use none. Estimated cost: ~half a day of
  mechanical rewrites + full gate re-verification.
- **Nothing performance-relevant suffers**: hot paths are array/int code that
  already reads like Java 8; no string concatenation in loops (so no indy-
  concat loss), `String.indexOf` intrinsics exist on 8. The one real cost is
  that *runtimes* of 8 are inherently slower (no compact strings etc.) — but
  that is the consumer's runtime choice, not a property of our bytecode; on
  modern JVMs, major-52 classes perform identically for this workload.
- **Tests/benchmarks can stay on 17+** (compile them at a higher `--release`
  in their own source sets — standard practice; or rewrite the few
  `String.repeat`s). ErrorProne runs fine compiling `--release 8` from a
  modern javac.
- Caveats to accept: no `@Serial` annotations (Java 14+) — the
  `serialVersionUID` constants are what matter and are Java 8-safe; no
  `StringBuilder.isEmpty()` (Java 15) — keep `length() == 0` (this triage
  already declined a Qodana suggestion for exactly this reason).

**Verdict: the Java 8 floor is achievable at trivial cost, buys real reach
(re2j-parity installability), and costs nothing measurable. Recommended as
part of Phase F** (one mechanical commit: `--release 8` for facade/core/asm +
the ~20 rewrites + a CI matrix row on a JDK 8 runtime to smoke-test).
Downgrading the *build* JVM to an old LTS: recommended against (see above).

## 3. Plan to "repeat review finds nothing"

Phased; each phase ends with full gate + quick-bench. Order maximizes
risk-retired per unit of churn.

**Phase A — determinizer/runner hazard removal (P1 #1-3, #7-8):**
stale-class-signature fix; zero-key remap; `stateRangeAt` overflow guard
(bound totalRanges or K); resolve `runStringAnchored` (fix the protocol or
assert-and-document unreachability with a proof comment); `tryStartFast`
invariants added to `computeFastPath` or branches deleted.

**Phase B — dead machinery + contract honesty (P1 #6, #13-14):** delete ψ
generation (or default `-Dtdfa.nofallback` semantics ON and rewrite the three
stale doc sites — prefer deletion: the metered dead code can cause spurious
"pattern too large"); meter `interferenceAnalysis` or fix WorkMeter's javadoc;
document the one-position-per-block invariant at `VAL_POS` and the same-value
rule; `rename` fail-fast on unmapped registers.

**Phase C — API freeze hygiene (P1 #15-20 + P2 API items):** `match(from)`
contract + bounds; internalize MatchResult ctor/`reconstructFixed`; `tag()`
bounds + NIL docs; thread-safety javadocs on every public class + the
mutable-CharSequence contract; SerialProxy versioning (or loud doc);
exception-consistency sweep; `equals/hashCode/toString` on value-ish classes;
`PatternSyntaxException.serialVersionUID`; `CompileOptions` javadoc example
fix; CaseFoldTable doc drift.

**Phase D — structure (thaw-pain reduction):** split Tdfa.java → Tdfa /
TdfaCompiler / DfaMinimizer(+keys); split TdfaRunner → SearchDfa / trace
instrument / table factory; mark-or-interface the ASM hook surface (P1 #9) +
name the magic `3`; COW-or-document the live arrays (P1 #4); unify the config
knob read timing (P1 #5); POSIX-mode alloc skip; `validate()` hardening.

**Phase E — ASM defense in depth (P1 #10-12 + P2):** `CheckClassAdapter`
verification of all dumped classes wired into `EmittedBytecodePolicyTest`
(turns emitter stack bugs into build failures — the single highest-value
test-side addition); override `getCommonSuperClass`; extend the INLINED budget
to `phiMasked` or exclude byMask DFAs; delete/mark-dead the unreachable
LITERAL ladder + `entryOkC`/`positionFlagsC`; fix the policy-test tmpdir race.

**Phase F — build/release (pending the user's tooling-stability decision):**
the two natural decade-stable paths are (a) plain `javac`/`jar` +
make-style scripts, or (b) keep Gradle but pin hard (wrapper sha256,
dependency verification, `--release 8`, single-source version). Either way:
CI (any form), japicmp baselines ×4, full Apache-2.0 LICENSE + headers via
Spotless, publish dry-run, oracle-jar tracking decision, script portability,
`LICENSE`/`README` truth-sync of the gate exclusions. Includes the **Java 8
floor** migration (see §1b: `--release 8` for facade/core/asm + ~20
mechanical rewrites; asm dependency ships major 49, re2j charter floor is
major 50, our generated classes are already V1_8) and a CI row running the
artifact on a JDK 8 runtime.

# Adversarial review: `Tdfa.java` (2,861 lines)

Read in full, plus `HistTable.java`, `WorkMeter.java`, `RegPool.java`, and cross-checks against `Tnfa.java`.

## 1. ARCHITECTURE

**The class is four programs in one file.** `Tdfa` is simultaneously: (a) the immutable compiled artifact + accessors (lines 25–477), (b) the determinization compiler (`Compiler`, 516–2461), (c) data types (`Config`, `DfaStateKey`, `Range`, `DfaStateBuilder`, 2464–2560), and (d) the minimizer (`DfaMinimizer`/`SigKey`/`OpSeq`, 2595–2860). The codebase *already knows* the right decomposition — `HistTable`, `WorkMeter`, `RegPool`, `FallbackOps`, `regopt.Cfg` were all extracted — `Tdfa.java` is the leftover monolith.

- `Compiler.compile(observer)` spans **lines 720–1366 (~647 lines)**: determinization loop, context-split, mask/stop-table computation, regopt dispatch, flat-array materialization, minimizer driving, fallback, re-sort, tier selection, ctor — 8 pipeline stages in one method, 4–5 nesting levels deep (733→837→846→879→881).
- Recommended split: `Tdfa` (artifact + `validate` + accessors, ~480 lines), `TdfaCompiler` (closure/step/regops/addState), `StopTable`/`FinalVariants` (the 917–988 + 1969–2026 mask machinery), `DfaMinimizer` + keys as top-level package-private classes, `Config`/`Range`/`DfaStateBuilder` into a `builder` package. `Compiler`'s per-compile-instance design is good and survives extraction unchanged.
- Responsibilities *inside* the compiler are actually cleanly separated (closure / step / regops / addState / tryMap are distinct methods); the tangling is at file granularity and in `compile()`'s stage-chain, not in the primitives.

## 2. CORRECTNESS HAZARDS

- **P0 — Minimizer merges states on 32-bit row hashes.** `fillAttrs` compresses the 64-cell stop-on-accept row and the 64-cell final-ops-by-mask row each into **one int** (`h = h*31 + cell`, Tdfa.java:2769–2773, 2775–2782) and puts that hash *into* the `SigKey` array. `SigKey.equals` then compares the arrays exactly — so two states whose rows **differ but whose polynomial hash collides** (p ≈ 2⁻³² per pair) land in the same Moore group and are merged, after which the merged state uses the representative's stop/φ row → **silently wrong match lengths**. With n up to 20,000 states (`MINIMIZE_MAX_STATES`), the birthday window over distinct rows is real, the failure is nondeterministic-in-practice, and nothing detects it. Compare full rows (64 extra ints/state in a per-compile map) or carry a 64-bit hash.
- **P1 — `addState` records a stale class signature for every first-of-shape tagged state.** `pendingClass`/`pendingClassHash` are only computed inside `if (candidates != null)` (Tdfa.java:2213–2234). When a shape is brand-new (`candidates == null`), line 2263 `stateClassIds.add(pendingClass)` and line 2267 `fresh.byClass.put(pendingClassHash, …)` store the **previous** closure's class (or `null`/`0L` for the very first state). Consequences: (a) the documented invariant at 2138–2146 — "no viable candidate is ever skipped" — is violated: a later identical closure probes `byClass.get(ch_true)` → miss → never tries `tryMap` against that state → **permanent missed merges**, inflating pre-minimization state count (spurious "pattern too large" near the 100 K cap, persistent bloat under `-Dtdfa.nominimize` or n>20 000); (b) theoretical NPE at 2225–2226 (`stored.length` with `stored == null`) if a probe hashes to the stale `0L` key.
- **P1 — zero-key sentinel conflation in the closure's visited set.** The open-addressing set uses `0` as EMPTY (Tdfa.java:1571–1577, 1636–1643), but key = `(state<<32)|mask`, and **NFA state 0 is the accept state** (`Tnfa.java:126`: `int accept = b.fresh()` is the first `fresh()` call, counter starts 0). So config `(accept, mask=0)` can never be marked visited. The subsumption cut (1614–1616, `submaskPopped` catches it via `maskBitset` bit 0) rescues the common case, but two `(0,0)` pushes issued during the *same* parent-expansion wave (before the first pop marks the bit — e.g. two ε-edges to accept explored back-to-back at 1617–1629) both survive and the kernel gets **duplicate accept configs**. Not a wrong-match bug (first-accept-winner logic is duplicate-tolerant) but it inflates kernels/`kernelsTotal`/keys nondeterministically-ish and is a structural landmine. Remap keys as `(state+1)<<32|mask` or reserve key 1.
- **P1 — mutable internals escape a public "immutable" class.** `stateMeta()`/`ranges()`/`ops()`/`entryHiPrefix()`/`stateEntryMask()`/`fixedBase()` etc. (Tdfa.java:419–469) return the live arrays on a `public final class` whose entire safety story is "consumers trust these arrays" (287–291). One stray write by any consumer corrupts a compiled pattern shared across threads, forever. `namedGroups` is wrapped (262) — the arrays should at minimum be documented as "live, do not mutate," or copied for external consumers with a package-private zero-copy path for the ASM backend.
- **P2 — `validate()` gaps** (308–375): `target` is only checked `>= stateCount` (332) — `target <= -2` passes the gate; array lengths vs `stateCount` are unchecked (a short `stateMeta` surfaces as raw AIOOBE *inside* the validator); op blocks are not checked for a missing `OP_END` terminator, so the j-loop at 341 can run off `ops` with a bare AIOOBE; the `rangeCount` pack `((k & 0xFFFF) << 1)` at 1131 **silently wraps** above 65,535 ranges/state with no guard at pack or validate time.
- **P2 — ownership/aliasing discipline is implicit.** `Config.regs` arrays are shared parent→child through the closure (1629) and symbol step (1861); the *only* clone-before-write is `transitionRegops` (1921). `transitionRegops` also **mutates its `configs` argument in place** (1941) — correct only because 862–863 call it before `addState` stores the list. `HistTable.bits()` returns live cache rows that `hasHistShared` then aliases (2193). None of this is documented at the field/method where a thawed maintainer would touch it.
- **P2 — `ProbeKey.equals` is asymmetric** (2077–2081: accepts `DfaStateKey`; `DfaStateKey.equals` rejects `ProbeKey`, 2496–2497). Works only because `HashMap.get` calls `query.equals(stored)`. The restriction is documented (2063–2067) but is a contract trap.
- **P2 — `stopMaskTableCache` "benign race" is not benign under the JMM** (127–151): non-volatile publication of a filled array can expose default values to a racing reader. `posFlagDepsCache` (int) is fine.

## 3. PERFORMANCE HAZARDS

- **P1 — `DfaMinimizer.stateRangeAt = new int[n * K]` (2674) can overflow int / OOM.** K = union of *all* states' breakpoints (2652–2669), bounded only by total ranges, which no cap covers (the state/kernel caps bound states and kernels, not ranges). n ≤ 20,000 × K ≈ 10⁵ ⇒ `n*K` > 2³¹ → `NegativeArraySizeException`, or 8 GB allocation just under the overflow line. The `MINIMIZE_MAX_STATES` gate is **dimensionally wrong** — it must also bound totalRanges or K. `transSig`'s per-state `new int[5+extra+K*3]` per Moore iteration (2795) compounds the same K in time and churn.
- **P2 — POSIX-mode waste:** `stateStopOnAcceptMask = new int[n*64]` is allocated and filled unconditionally (916–917) even when `longest`, then never used (`if (!longest)` at 954, 1338) — 25.6 MB of churn on a 100 K-state POSIX compile, plus the minimizer lugs it around.
- **P2 — Moore loop allocations:** fresh `SigKey` + `int[]` + boxed `HashMap<SigKey,Integer>` per state per iteration (2722–2730); `OpSeq` wrapper per offset intern (2704). Bounded by the 20 K gate, but heavy on wide-Unicode DFAs.
- **P2 — `tableDeps`** (184–200) is O(bits·n·64) on first `posFlagDeps()` call — fine once, but it's on the *instance*, post-compile; a consumer calling it per-match would pay repeatedly (nothing marks it cached-for-external-use).

## 5. API DESIGN

- **Config knobs are split-brained (P1):** `MINIMIZE_ENABLED`/`MINIMIZE_MAX_STATES`/`REGOPT_*`/`FALLBACK_ENABLED`/`DEBUG` are `static final` read at **class-init** (486–514, plus a *duplicate* `Compiler.debug` at 1508), while `maxStates`/`maxKernelsTotal`/`maxClosure`/meter-budget are read **per compile** (524, 597, 604, 608 — with a comment at 594 explicitly saying "read per-compile so tests can override"). A test (or ops runtune) setting `-Dtdfa.nominimize` after first use silently no-ops. ## 6. TESTABILITY

- Gaps: the meter can't actually be injected (constructed internally at 524 — no way to give a test a tiny budget without a system property); debug output goes straight to `System.err` (725, 739–741, 861, 884, 1252, …) bypassing the existing `CompileObserver` hook — untestable side channel; the class-init-frozen knobs (Section 5) make minimization/regopt/fallback toggle-paths untestable in a JVM that has already compiled one pattern.

# Adversarial Review: `TdfaRunner.java` (2,328 lines)

**Verdict up front:** The "one brain" design is defensible — the ASM backend delegates strategy pieces to monomorphic calls on a `final` class and the conformance test locks ladder ordering. The real freeze risks are (a) **per-runner mutable memos that violate the documented thread-safety contract**, (b) **one walk that still uses the pre-fuzz-round-11 priority protocol**, and (c) a 2,328-line file carrying six separable concerns.

## P0 — must fix before freeze

**P0-1. `SearchDfa` is unsynchronized shared mutable state, but the engine contract promises thread safety.**
`RegexEngine.java:17-18` documents: *"Implementations must be effectively immutable and safe for concurrent use from multiple threads."* `TdfaRunner.java:104-106` repeats the intent ("A runner is shared when its Pattern is used from several threads... so scratch buffers are ThreadLocal"). But the lazy search-DFA memo — `searchDfa` (TdfaRunner.java:675, constructed at :175) — mutates plain `HashMap`/`ArrayList` (`rowById`, `rowWords`, `rowBlockIds`, `rowHasBlock`, `blockById`, `blocks`, plain `boolean capped` — :865-871) with **zero synchronization** from `triggerScan` (:1015-1048) → `bmpTransition` (:998-1005) → `buildBlock` (:960-995) → `internRow` (:883-896). Two threads calling `find()`/`match()` on one shared `Pattern` with windows ≥ `SDFA_MIN_WINDOW` (2048) race `rowWords.add()` vs `rowWords.get()` (lost elements → stale/null reads → NPE in `accept()` :898-902, or `IndexOutOfBounds`), and concurrent `rowById.put` can desync map from list. Note the caps comment (:661-663) even *calls it* a "ThreadLocal memo" — it isn't; the comment is wrong. Fix is cheap: synchronize `buildBlock`/`internRow` (memo build is rare; the read path via materialized blocks is lock-free) or make the whole memo per-thread. Either way, fix the comment.

**P0-2. `walkBlockIdx` is unsafely published; a stale cell reads as block id 0 → silently wrong dispatch.**
`walkRangeIndex` (:806-826): the per-state `int[128]` is created, filled with −1, and stored into `walkBlockIdx[state]` (:810-813) via **plain writes**; readers on other threads read `walkBlockIdx[state]` and `idx[b]` (:807, :816) without any happens-before edge. A racing thread can observe the array reference but stale default `0` cells: `id == -1` fails, `id < 0` fails, and — if any block exists — `arr[0][c & 511]` (:820-823) returns **another state's range index** → wrong transition → wrong match, silently. The `walkBlocksArr` volatile/COW scheme (:94, :845-848) protects block *contents* but not the `idx` arrays. On Apple Silicon (this repo's own platform, aarch64) this is not theoretical. Same fix family as P0-1.

## P1 — should fix before freeze

**P1-1. `runStringAnchored` still uses the *old* transition-priority protocol — the fuzz-round-11 fix was not applied uniformly.**
The documented ownership protocol ("MOST SPECIFIC satisfied mask wins (popcount), ties to lowest index; a dead owning context kills the walk — no fallthrough") is implemented in `extractFrom` (:556-583), `runStringMatchFrom` (:1910-1929), and `runGeneric` (:2015-2030). But `runStringAnchored`'s non-disjoint branch (:1763-1793) keeps pure lowest-index priority and treats dead markers as *transparent* (`if (target < 0) continue;` :1774) — exactly the shadowing bug shape the comment at :553-557 says was fixed. `matches()` (:321-322) reaches this branch for any non-fastPath DFA. Consequence: `matches()` can return `true` where `match()`/`find()` find nothing, on overlapping-mask-context patterns. Either fix the branch or prove non-disjoint+masked DFAs can't reach it and assert so.

**P1-2. `tryStartFast` diverges from `extractFrom` in two ways; both are presumably dead under fastPath, but nothing states or enforces that.**
(a) On a position-suppressed accept (`cell < 0`) it does `continue` (:1639), which **skips the transition** — freezing the walk state while `pos` advances; `extractFrom` falls through to the transition (:491-495). (b) It never resets `posFlags = -1` after a transition (:1664; compare extractFrom :613, matchFrom :1943, anchored :1796, generic :2042), so a stale prior-position `posFlags` can feed `fm[state*64+posFlags]` (:1638) and `stopNow` (:1642, :1648). Both are only safe if fastPath guarantees `finalOpsByMask == null ∧ stopMaskUniform != null` — an invariant `computeFastPath` (:2253-2262) does *not* check (it checks entry/accept/required masks only). Add the invariant to `computeFastPath` or delete the branches; as written this is a trap for the first thaw.

**P1-3. The de-facto ASM API is a scattered, unmarked 18-member surface.**
ASM calls (TdfaAsmBackend.java:497-615, 380-400): `trace`, `anyMatch`, `leftmostStart`, `matches`, `find`, `match`, `LSS_BUDGET`, `detectLiteralNeedle`, `literalNeedle`, `literalIndexOf`, `needleEndOverlapsPair`, `restartExtract`, `startBits`, `candScanMax`, `fastPath`, `originSimBudget`, `originSimLeftmost`, `triggerScanTop`, `booleanMatchFrom`, plus the `MatchHolder` ctor referenced by internal name (:22, :471). Only one banner comment (:1231-1235) marks *some* of these; the rest (`anyMatch` :254, `leftmostStart` :275, `trace` :233, `detectLiteralNeedle` :688, `MatchHolder` :625) look like ordinary public methods. Signatures are resolved via string constants, so javac won't catch a rename — it's `NoSuchMethodError` at pattern-compile time, and the conformance test only guards *ordering*, not signatures. Before freeze: extract a `SearchLadder`-style interface (or at minimum a `@ASMHook` javadoc tag + one grouped section) and document the call *contract* (ordering, argument ranges, `LSS_BUDGET` protocol).

**P1-4. Magic number `3` (adaptive boolean-filter threshold) duplicated across backends with no name.**
`fails >= 3` at :416 and :1563, and `ICONST_3` hand-emitted in TdfaAsmBackend.java:541. Change one, silently desync the other's perf profile (results stay identical, which is worse — nobody notices). Name it (`CAND_FAILS_BEFORE_BOOL_FILTER`) and expose via a hook like `candScanMax()`.

## P2 — nice to fix

- **Dead code:** `SearchDfa.step()` (:935-946, superseded by `transition()`); `pickFinalOpsOff` (:2074-2080, `private`, never called — only the ASM backend's *own* copy per its javadoc :2088-2091) and its exclusively-read fields `stateIsFallback`/`stateFallbackOpsOff` (:170-171); `lastAcceptState` dead stores in three walks (:467, :1628, :1954 + assignments); `tryStartFast`'s unused `originFrom` param (:1601). Orphaned javadoc blocks with no declaration: :852-858 (doc for the deleted `computeNeedsWordFlags`), :1237 (needle doc duplicating :676-682), :2100-2108 (superseded `stopNow` doc stacked on the real one at :2109).
- **Perf:** `Boolean.getBoolean("tdfa.trace")` — a property-table lookup — inside the `WALK_RESTART` loop (:434), inconsistent with the cached `WTRACE` (:68). `runGeneric` allocates fresh `regs` per restart (:1951) and has no trigger/`anyMatch` pre-check, so generic-`CharSequence` `find`/`match` retain the worst-case O(n²) restart shape (:1948-2054); `leftmostStart` on non-String input copies the whole tail via `toString()` (:308, :314). `SCRATCH.get()` re-fetched per candidate in cand scans (:454) rather than hoisted. `delta()` allocates `int[nw]` per supplementary codepoint during memoized scans (:905-931) — bounded by caps, but allocation-heavy on astral-plane text.
- **State retention:** `SCRATCH` (:116) and `TRACE_BUF` (:228) ThreadLocals are never evicted — a thread that once matched a 234K-state DFA retains ~2 MB of scratch forever; if `TRACE` is enabled in a live process, `TRACE_BUF` grows unbounded until `traceSnapshot()`. Documented trade-off at best; a `clear()`/size note in the class javadoc would do.
- **Robustness:** `detectLiteralNeedle` catches all `RuntimeException` (:751-753) — masks genuine table bugs as "not a literal". `match(input, from)` doesn't validate `from` (:370) → raw `StringIndexOutOfBounds` from deep inside `positionFlags`. The 16-bit range-count packing (`(meta >>> 1) & 0xFFFF`, :522 etc.) is unvalidated in `Tdfa.validate` — a >65,535-range state would silently truncate. `from + budget` (:1350) can overflow for `from` near `Integer.MAX_VALUE`.
- **Style:** raw surrogate literals (:299, :348, :747, :1246) vs named `Character.MIN_*_SURROGATE` (:2303-2305) in the same file; `positionFlags` vs `positionFlagsCS` are byte-identical bodies (:2118-2147, intentional String-specialization, but nothing says so — drift risk); the mixed ternary at :300 (`fast ? matchFromFast(...) : runStringMatchFrom(...) >= 0`) begs parenthesization; `64` (posFlags stride) appears as a literal at every table index site.
- **Decomposition (architecture):** natural seams are real and cheap: `SearchDfa` (:861-1006) → own file; tracing instrument (:197-246) → own file; table/memo builders (`buildAsciiTarget` :2216, `buildAsciiRangeFlat` :2235, `buildStartBits` :763, `buildWordBits` :783, `checkRangesDisjoint` :2150, walk blocks :801-850) → a `RunnerTables` factory. What remains (~1,200 lines: ladder + walk engines) is cohesive. The scan loops themselves are consistent — each candidate loop starts exactly where the prior exact walk left off (`leftmostStart` :296 from `from`; `find` :346 and both extracts :412/:1559 from `from+1` after the exact-from walk; `findFast` :1475 from 0 with no prior walk), restart loops land exactly on the kill-point boundary (`w-1` then `from+1` :429; `Math.max(w,1)` :356; `s <= to` :1272), and every surrogate edge is guarded (pair-interior skips in all cand scans, `decode`+`width` in all walks, both needle ends checked :1257-1263, lone-surrogate needles rejected :745-749).

## Genuinely excellent

- **`posFlagDeps()` derived from the tables themselves** (Tdfa.java:153-200) replacing three hand-kept per-consumer models, plus the construction-time `validate()` gate (Tdfa.java:290-375) that turns silent wrong-match bugs into constructor exceptions.
- **The strategy-trace conformance design** (:197-246): recording decision points in both backends from one template and asserting sequence equality is a structural — not statistical — guard against the two ladders drifting, at near-zero disabled cost.

I tried to break `(?i)[\W]` with cross-category orbits (µ/μ U+00B5/U+03BC, Ω/ω U+2126/U+03C9): the double fold at Parser.java:340 of the pre-complemented set (Parser.java:386) is semantically a no-op because orbits don't straddle the complement — correct, though only by this invariant (see P2-1).
- **`Alphabet` chokepoint** (Alphabet.java:19-44) — one decode/width/pairInterior definition shared by pattern and match sides; supplementary codepoints and lone surrogates are handled coherently everywhere I traced (Parser.java:161-181, 555-557, 674-681).

## P0

**P0-1. No repeat-count cap; `{n}` desugaring explodes before any budget can fire.**
- `parseBraces` accepts any int: Parser.java:834-852. No cap anywhere.
- `Tnfa.Builder.buildRepeat` materializes `min` body copies: Tnfa.java:417-418 (`for (int i = 0; i < min; i++) mandatory.add(body);`), then builds one state+edges per copy (Tnfa.java:171-267).
- All compile budgets (`tdfa.max.states`, WorkMeter) live in **Tdfa determinization** (Tdfa.java:1586, 2281, WorkMeter.java:26) — i.e., *after* `Tnfa.build` has already allocated everything. `a{500000000}` OOMs or hangs in the Builder with a raw `OutOfMemoryError`, which `CompiledRegex.pipeline` cannot translate (it catches only `RuntimeException`, CompiledRegex.java:71-75).
- re2j parity: re2j's `parseRepeat` contains `sipush 1000` + `invalid repeat count` (verified in bytecode) — re2j rejects `{1001}` and up at parse time. The stated API contract is re2j drop-in parity; this is both a DoS vector and a parity break. Nested products like `(x{1000}){1000}` (10⁶ shared refs, 10⁶ NFA states, no Builder ceiling) also bypass every cap, though re2j is comparably fragile there — the single-quantifier cap is the non-negotiable part.
- Bonus in the same lines: `{2147483648}` throws raw `NumberFormatException` from `Integer.parseInt` (Parser.java:840, 846; same for `\x{…}` at 573, 811) — translated to a PSE at the facade, but with the message `"For input string: \"2147483648\""` instead of re2j's `invalid repeat count`, and no index. Also `Character.isDigit` (Parser.java:838, 845) accepts Arabic-Indic digits, so `a{٥}` is parsed as `a{5}`; re2j (ASCII-digit checks) treats it as literal — silent divergence.

**P0-2. No nesting-depth cap → `StackOverflowError` through the public API.**
- Recursion cycle `parseAlt → parseConcat → parseRepeat → parseAtom → parseGroup → parseAlt` (Parser.java:98-182) with no depth counter. `"(".repeat(20000)` overflows the default JVM stack (~5 frames/level).
- `StackOverflowError` is an `Error`: it escapes `CompiledRegex.pipeline`'s `catch (RuntimeException)` (CompiledRegex.java:71-75) as a raw SOE from `Pattern.compile` — uncatchable by the re2j-parity exception contract.
- re2j's parser is **iterative** (explicit `Parser$Stack`, confirmed in bytecode), so it never SOEs. A simple depth counter throwing `fail(...)` at e.g. 1000 (matching RE2's practice) fixes both the crash and the parity.

## P1

**P1-1. Inline flags leak out of enclosing groups.**
- Flags are saved/restored only for the `(?flags:` form (Parser.java:236-246, 276-282). A bare `( ... )` or `(?: ... )` group never saves or restores. `((?i)a)b` therefore case-folds `b`; `((?m)a)$` similarly.
- re2j restores flags at every `)` (bytecode: `)` handler does `this.flags = leftParenFrame.flags`), and PCRE scopes `(?i)` to the end of the enclosing group. `parseGroup` should save flags at `expect('(')` and restore at `expect(')')` unconditionally. This also silently corrupts `ParseResult.multiline()` (Parser.java:85-87), which reports the *final* flag state.

**P1-2. Quantifier with no preceding atom silently becomes a literal.**
- `parseAtom`'s fallthrough (Parser.java:174-181) treats `*`, `+`, `?` as ordinary literals. `*a` compiles as `Symbol('*') Symbol('a')` and *matches the string `*a`*; `a**` becomes `(a*)` + literal `*`. re2j throws `missing argument to repetition operator` (string confirmed in re2j bytecode); PCRE errors identically. Silent misparse is the worst failure mode a regex parser can have — this must be `fail(this, "missing argument to repetition operator")`.

**P1-3. `parseHexChar`/`parseHexEscape` accept lone-surrogate and boundary values with no issue… but `parseBraces` overflow handling is only the tip: error-path message parity.**
Grouping the remaining error-quality issues: besides P0-1's NFE messages, the possessive-quantifier path throws `UnsupportedOperationException` (Parser.java:132) — a different exception family from `fail()`'s IAE — so direct users of the documented "composable-pipeline entry point" (`Parser.parseResult`, Parser.java:77-79; also `Tnfa.compile`, Tnfa.java:100-134, which bypasses `CompiledRegex.translate`) get three exception types (IAE, UOE, NFE) with inconsistent message formats. `fail()`'s index is also the *post-consumption* position (Parser.java:884-886), so e.g. the `inverted range in class` error (Parser.java:326) points one past the offending endpoint. And the flag-error message renders as `(?+P` — the `+` is a concatenation artifact, not syntax (Parser.java:226).

**P1-4. `readGroupName` accepts any character up to `>`.**
- Parser.java:874-882: `(?<a b>`, `(?<1a>`, `(?<->` all parse. re2j validates via `isValidCaptureName` (confirmed in bytecode) and rejects with `invalid named capture`. Given group names surface through the public `namedGroups()` API (ParseResult.java:31), invalid names here become API-visible garbage downstream.

## P2

1. **`(?i)` class fold is O(universe) with boxed lookups.** `foldExpandRanges` iterates every codepoint of every range (Parser.java:348-357); for `(?i)[\W]`/`(?i)[\P{L}]`/`(?i)[a-\x{10FFFF}]` that's ~1.1M iterations × boxed `HashMap.get(Integer)` (CaseFoldTable.java:48) per compile, purely to re-fold an already orbit-closed set (no-op, see "excellent"). Fold only positive-contributed ranges, or cache complements.
2. **CharClass/AST immutability is by convention.** `CharClass.ranges` is a public mutable `int[]` with no defensive copy (CharClass.java:11-16 — `normalize` even returns the caller's array when already sorted); `DOT/DOTALL/...` are static singletons shared by every parse (Parser.java:930-937); `Ast.Tag.fixedOn/fixedOffset` are public mutable (Ast.java:27-28, at least documented). One stray `ranges[0]=...` corrupts every subsequent compile. Threads may share ASTs only if nobody mutates — not "safely immutable."
3. **Five parallel instanceof-walks of the AST** with no visitor: `FixedTags.walk` (FixedTags.java:61-139), `Tnfa.build` (Tnfa.java:171-267), `collectFixedAnnotations` (Tnfa.java:138-152), `collectGroups` (Tnfa.java:270-282), `isNullable` (Tnfa.java:291-311). Adding a node type requires 5 coordinated edits; the only guard is a runtime `IllegalStateException("unknown ast")`. Also `collectFixedAnnotations` duplicates work `FixedTags` could do during its walk.
4. **Duplication:** `parseHexChar` vs `parseHexEscape` are near-clones (Parser.java:561-583 vs 799-822 — the class variant could `return literalAtom(...)`); octal parsing duplicated (Parser.java:523-535 vs 591-603); `parseUnicodeEscape` vs `appendUnicodeToRanges` duplicate the entire name/negation/fold/lookup sequence including the truth table (Parser.java:694-732); `appendUnicodeToRanges` has a dead `unused` parameter (Parser.java:719); the 1-arg `Parser(String)` constructor is dead (Parser.java:52).
5. **`{0,0}` drops body ntags silently.** `(a){0,0}` desugars to bare `Empty` (Tnfa.java:414-454 falls through with empty mandatory and no suffix), emitting neither tags nor ntags. It's sound *only* because a group's tags are syntactically unique, so they can never have a stale value — but that's exactly the class of subtlety this file documents elsewhere; the quest case (Tnfa.java:321-337) meticulously emits ntags, so the asymmetry looks like an oversight rather than a decision. Deserves a comment or test.
6. **FixedTags arithmetic can overflow silently.** `add`/`mul` (FixedTags.java:141-149) are NaN-poisoned but not overflow-poisoned; `mul(r.min, k1)` with a large `min` × multi-char body wraps to garbage offsets. Practically masked by P0-1 (such patterns OOM first), but if a cap lands, add a saturation check.
7. **Misc:** `CharClass.toString` casts supplementary codepoints to `char` (CharClass.java:94 — garbage debug output); binary-search threshold `8` magic (CharClass.java:59); state numbering is right-to-left from `entryTo` (Tnfa.java:224-229) — fine, but nowhere documented, which hurts debugging; alt-branch priority `i + 1` convention undocumented at Tnfa.java:259; `Tnfa` constructor takes 19 params and `Builder.build` 10 (Tnfa.java:65-70, 457-459) — a config/record would help; `Boolean.getProperty("tdfa.debug")` + `System.err` debug leftover (Tnfa.java:120-124); `ParseResult`'s `Map.copyOf` drops LinkedHashMap order (ParseResult.java:33-35) — unspecified iteration order for named groups; stale comment claiming supplementary codepoints have no fold table (Parser.java:144) while `CaseFoldTable.buildCache` scans 0..0x10FFFF (CaseFoldTable.java:57), and conversely CaseFoldTable's javadoc says "BMP" (line 9).

## FixedTags (Q6)

Does exactly what BT22 §6.4 requires, and the implementation is sound: I traced the right-to-left concat walk (it fixes *open* tags onto close tags — equivalent reconstruction, though the javadoc's "top-down/bottom-up" phrasing never mentions the direction), the NaN≠NaN alt agreement that correctly poisons `(a*|b)*` (FixedTags.java:99-127 with the worked example), repeat contributing only when `min==max` (FixedTags.java:128-137), and UTF-16-width poisoning for mixed-width classes (CharClass.java:82-88, FixedTags.java:68-76) — that's a real bug class they dodged (`.` must poison, supplementary-only must count 2). # Adversarial review: ASM bytecode backend (`TdfaAsmBackend`, `ShellEmitter`, `EmittedBytecodePolicyTest`)

## What's excellent

- **Delegation-first architecture ("one brain, one ladder")** — the search strategy lives in `TdfaRunner`; generated code calls monomorphic final-class hooks and owns only the walk leaf (TdfaAsmBackend.java:82-93). This structurally minimizes the transcription surface, and `StrategyConformanceTest` asserting *trace equality* (not just output parity) between VM and ASM is a genuinely strong drift guard.
- **The 64KB-method-limit history is documented at the exact emission sites** with the structural fix (runtime loops over the `Tdfa` arg instead of unrolled IASTOREs in `<clinit>`) — TdfaAsmBackend.java:129-135, 243-252. The `pickMode` INLINED/DELEGATE budget (1969-1995) is a real pre-emission limit, not wishful thinking.
- **`EmittedBytecodePolicyTest`'s reflective receiver-finality check** (EmittedBytecodePolicyTest.java:140-150) enforces the devirtualization invariant structurally (not by allowlist), and correctly treats unloadable receivers as violations.

## P0 findings

**P0-1. The entire fallback story has an Error-shaped hole: `VerifyError`/`LinkageError`/`NoSuchFieldError`/`IllegalAccessError` escape every handler.**
- `TdfaAsmBackend.generate()` catches only `Exception` (TdfaAsmBackend.java:73-75); `ShellEmitter.emit()` catches only `ReflectiveOperationException` (ShellEmitter.java:329-331); `PatternCompiler` catches only `RuntimeException` at both fallback sites (PatternCompiler.java:93, 109). I verified **nothing in the pipeline catches `Throwable`/`LinkageError`**. A `VerifyError` from `defineClass` inside `Class.forName` (TdfaAsmBackend.java:70) propagates raw out of `Pattern.compile` — no interpreter fallback, no `CompiledRegex.translate` mapping.
- Worse, some linkage is *lazy*: the shells' `GETFIELD/PUTFIELD` on `core.Matcher` fields (`hasMatch`, `lastMatchEnd`, `appendPos`, `input`… ShellEmitter.java:117-153, 184-251) resolve at **first `find()`/`matches()` call**, not at emission — so a descriptor mismatch surfaces as a `NoSuchFieldError` mid-match in user code, after compile succeeded.
- Why P0 before a freeze: this is the safety net for every other finding. Any post-thaw emitter regression becomes a hard production crash instead of the documented "falls back to the shared implementation" behavior (PatternCompiler.java:24-26 promises exactly that). Cheap fix window is *now*: catch `LinkageError` (or `Throwable`) in `PatternCompiler`'s two fallback sites.

**P0-2. Nothing verifies the emitted bytecode — the policy test would NOT catch stack/local-slot bugs.**
- `EmittedBytecodePolicyTest` audits only call opcodes (visitMethodInsn, lines 84-97). There is no `CheckClassAdapter.verify(...)`/`AnalyzerAdapter` pass anywhere in the repo. The only verifier of manual stack-shape reasoning (e.g. the currWord value held live across the `currDone` label merge at TdfaAsmBackend.java:1474-1498, or the `lo = max(...,0)` DUP/POP/branch dance at 314-324) is the JVM itself — at `Class.forName(..., true, cl)` — which per P0-1 throws an uncaught `Error`.
- Fix before freeze: add `CheckClassAdapter` verification of the dumped classes to the policy test (ASM is already on the test classpath), turning verifier-class emitter bugs into build failures instead of production `VerifyError`s.

## P1 findings

**P1-1. `COMPUTE_FRAMES` with the default `getCommonSuperClass()` — no override anywhere** (TdfaAsmBackend.java:94; ShellEmitter.java:91, 260).
- ASM's default implementation loads classes via *the ClassWriter's own loader* (the ASM bundle's loader). Two consequences:
  - **ShellEmitter is designed to not see its facade types**: its Javadoc brags the facade classes "appear exclusively as internal-name/descriptor strings" because the module graph is facade → asm → core (ShellEmitter.java:21-27). This means any future control-flow join that merges two facade-typed references (e.g. a local typed both `PatternMatcher` and `GenNNNMatcher`) makes `getCommonSuperClass` do `Class.forName("io.github.jemmix.tdfa.TDFAPattern")` from a loader that *cannot* see it → `ClassNotFoundException` inside `toByteArray()`. It works today only because I verified every current merge point in both emitters joins ints, nulls, or identical types. That invariant is undocumented and unenforced.
  - Same trap for the generated engine's own type (`GenN` is invisible to the writer's loader — defined only in the child) if any frame ever needs it merged.
- Explicitly noting what the prompt asked: the **classic COMPUTE_FRAMES-under-loader-lock deadlock does NOT apply here** — both emitters finish `toByteArray()` *before* creating/locking the `GenClassLoader` (TdfaAsmBackend.java:63-70; ShellEmitter.java:257/305 → 315-321). Good. But the wrong-loader resolution landmine remains. Fix: override `getCommonSuperClass` to take an explicit loader (or use the `ClassLoader`-parametrized constructor pattern) before freeze.

**P1-2. `phiMasked` size is not covered by the emission budget — limits not fully enforced before emission.**
- `estimateInlinedBytes` counts final-ops **once per accept state** via `sfo` (TdfaAsmBackend.java:2024-2028), but `genPhiMasked` emits one ops block **per distinct `byMask` cell** — up to 64 per state (TdfaAsmBackend.java:1330-1346). `computeFastPath` (2048-2054) does not exclude `stateFinalOpsByMask() != null`, so a fastPath DFA with rich per-posFlag final-op tables can legally reach INLINED and blow the 64KB method cap in `phiMasked` while `extractOne` looks small. Result: `MethodTooLargeException` at emission → RuntimeException → *silent* interpreter fallback (PatternCompiler.java:109-114), a perf cliff visible only if a `CompileObserver` is wired.
- Same family: dead-marker ranges (target < 0) are *skipped* in the estimate (2016) but their range-checks **are emitted** (1159-1162, 1175-1181, 1195-1198), and the per-range/per-op constants (25B/7B) are admitted lower bounds (comment at 1989-1994). The 30KB→64KB headroom is empirical, not structural.

**P1-3. Dead-but-maintained transcription surfaces — the primary silent-drift vectors post-thaw.**
- **The LITERAL ladder in `genMatch` is unreachable**: any pattern with a literal needle is forced to DELEGATE (TdfaAsmBackend.java:91-92), so lines 441-477 (needle fetch, `emitTrace("LITERAL")`, `literalIndexOf`, holder construction) never execute — yet must stay in sync with `detectLiteralNeedle` and `runStringExtractFast`'s literal branch (TdfaRunner.java:1539-1543). If `detectLiteralNeedle` ever narrows, this path *resurrects untested*.
- **`entryOkC` + `positionFlagsC` are emitted into every INLINED class but never called**: INLINED requires all `stateEntryMask == 0` (2051), so the only call site (1222, guarded compile-time at 1207) is dead, and `positionFlagsC` is only reachable from `entryOkC` (724). Two consequences: never-linked descriptors that a core refactor can silently rot (no compile-time check, no test executes them), and **`positionFlags` semantics are transcribed twice** — `emitPFInline` (1358-1512, live) vs `genPositionFlagsC` (742-904, dead) — a standing divergence hazard.
- **The specificity sort is a provable no-op**: `computeFastPath` requires all range `reqMask == 0` (2053), so `Integer.bitCount` is always 0, the comparator never reorders (and `return c != 0 ? c : 0` at 1165 is a literally redundant conditional), yet the comment (1152-1157) documents live "fuzz round 11" semantics that must actually live in `TdfaRunner`'s scan for DELEGATE shapes. A reader post-thaw will wrongly believe this sort is load-bearing.

**P1-4. Load-bearing descriptor strings with lazy linkage = runtime-only breakage on core refactors.**
- Every cross-module coupling is a string: `MatchResult.<init>([IIIII)V` (TdfaAsmBackend.java:698), `reconstructFixed([II[I[I)V` (686), `RegPool.take(I)[I` (962), `Pattern$Utf8.decode` (ShellEmitter.java:299), the `core.Matcher` protected-field GETFIELDs (117-153), `TDFAPattern` ctor signature (273-274). A post-thaw signature change compiles cleanly in the emitter and detonates at link time (`NoSuchMethodError`, per P0-1 uncaught), *only* on code paths the conformance catalog happens to execute. Combined with the dead paths of P1-3, some of these (e.g. `entryOkC`'s descriptor) could be wrong **today** and nothing would notice.

## P2 findings

- **P2-1. Inconsistent local-slot discipline.** `emitRunCore` uses named constants (922-925) — good — but `genMatch` documents its map in a comment then uses raw `3`–`11` throughout (420-421 vs 485-616), and `genInit` uses magic raw slots 2-14 with comment-only maps (210-211, 265). Freeze hazard: anyone running `buildPatchedOracle` (or `-Pfuzz.patchedOracle=true`) dirties a tracked binary that could get accidentally committed, silently drifting the oracle from its patches. Decide: either untrack it and wire `buildPatchedOracle` into the rebar suite's task graph, or keep it tracked, delete the ignore rule, and make the build reproducible (`jar --date`, strip timestamps).

**P1-2. `build-patched.sh` is macOS-only.** Line 55: `sed -i '' "s/fixLEVEL/…/` — BSD sed syntax; on GNU sed this fails. The committed jar saves `check` on Linux today, but any rebuild path (`buildPatchedOracle`, fuzz-patched) breaks off-macOS. `bench-regression.sh:17` handles the scutil/hostname difference properly; this script doesn't.

**P1-3. Timing-based hard gates with thin headroom.** Wall-clock asserts inside `check`:
- `CompileLatencyGuardTest.java:56` — `BUDGET_MS = 5_000`, while its own javadoc (line 49-51) says worst measured ~3 s → 1.67× headroom on a machine family documented to drift ±30%.
- `RedosBatteryTest.java:40-41` — `COMPILE_BOUND_MS = 5_000` (measured 0.9–3 s), `REJECT_BOUND_MS = 60_000` vs measured 6–19 s.
- `RegexTest.java:277/285/317/338` — `< 2_000 ms` scans (large headroom, lower risk).

On loaded CI runners these are your likeliest fresh-machine flakes. The `InliningGuardTest` javadoc itself admits the class of problem ("would flake exactly like the compile-latency guard does on a loaded machine" — `InliningGuardTest.java:35-36`).

**P1-4. No toolchain / no `--release`.** All modules set only `sourceCompatibility/targetCompatibility 17` (e.g. `build.gradle:8-11`). Building on JDK 26 (as here, and per README's JDK 26 numbers) compiles against the *current* platform classes — no protection against post-17 API leakage into class files, and class files vary by which JDK runs Gradle. README.md:265 claims "JDK 17+"; that configuration has never been tested (no CI matrix, TODO.md:995). Same root as unchecked "Reproducible builds" (TODO.md:999). Fix pre-freeze: `options.release = 17` or Java toolchains.

**P1-5. Bench scripts assemble classpaths by scraping `~/.gradle/caches`.** `bench-rebar.sh:25-33` and `bench-regression.sh:31` do `find ~/.gradle/caches/modules-2 -name 'asm-9.9.1.jar'`, with dependency versions **hardcoded in shell, duplicated from build.gradle**. A version bump in Gradle silently breaks the scripts (empty `-cp` entries → `NoClassDefFoundError` at runtime, not a clear error). Worse, `bench-rebar.sh:23` pipes `./gradlew compileJmhJava` through `grep … || true`, **swallowing compile failures** before `exec java` dies confusingly. This exact script already "silently broke Aug-18" once (TODO.md:31-33 admits it).

**P1-6. No dependency verification or locking.** `gradle/` contains only the wrapper — no `verification-metadata.xml`, no `gradle.lockfile`; wrapper properties lack `distributionSha256Sum` and set `retries=0` (`gradle/wrapper/gradle-wrapper.properties:3-6`). Versions themselves are properly pinned (no dynamic versions anywhere — good), and the JitPack dep is commit-pinned (`benchmarks/micro/build.gradle:16`), but JitPack is a build-on-demand service: if DataDog's repo or JitPack's cached build of `f437ac8d…` ever becomes unavailable, benchmark builds stop resolving. Consider mirroring that jar into `vendor/archives` like everything else.

## P2 — flag before signing off

- **P2-1. Rebar suite skips on unexpected compile exceptions.** `RebarScenarioParityTest.java:246-265`: only budget rejections fail; *any other* compile exception → `assumeTrue(false)` = gray SKIP. A future `IllegalStateException` bug on in-scope scenarios would shrink the green set, not fail the gate. Defensible for a vendored corpus, but deserves a skip-count assertion (e.g. fail if skips exceed a recorded constant).
- **P2-2. Gate scope not fully documented in README.** `check` excludes: `*InliningGuard*` (`tests/unit/build.gradle:26`, separate action), the fuzz soak (`-Pfuzz.minutes=480`, default 8 h), patched-oracle fuzzing, BOMB_SCENARIOS (opt-in, needs `-Dtdfa.max.states=250000` + ≥1–6 GB, `RebarScenarioParityTest.java:200-204`), and every benchmark. README:256 says "run everything" — the exclusions live only in build-file comments; README never mentions the JIT guard at all (grep: 0 hits).
- **P2-3. "Deterministic compilation" is an open TODO** (`TODO.md:894`) — same regex → identical TDFA across runs is not guaranteed. For a frozen engine, users diffing outputs or caching compiled patterns will notice.
- **P2-4. LICENSE is a 436-byte stub**, not the full Apache-2.0 text; no per-file license headers (any file starts at `package`, spot-checked `core/.../CompiledRegex.java:1`). Vendored-license hygiene, by contrast, is meticulous (`vendor/README.md:85-93`).
- **P2-5. `prepareVendor` up-to-date hole**: declared outputs are only `build/generated` (root `build.gradle:33`), but the rebar suite consumes `build/vendor/rebar/pristine/…` (`tests/parity/rebar/build.gradle:24-25`). If `build/vendor` is deleted while `build/generated` survives, the task is UP-TO-DATE and rebar tests fail at runtime. Edge case; a `clean` wipes both.
- **P2-6. Dep staleness at thaw**: junit-bom 5.10.2, assertj 3.25.3, guava 33.0.0-jre, jmh 1.37 / plugin 0.7.3, ASM 9.9.1 — all fine today, but a thaw after a long freeze must re-audit all of these (plus Gradle 9.5.0 itself; the build already emits "incompatible with Gradle 10" deprecation warnings on every run — visible in my fresh-clone output).
- **P2-7. Minor script nits**: `fuzz-soak.sh` uses `set -u` only (deliberate and documented — findings must not kill the soak — but no `pipefail`); fuzz default seed is `currentTimeMillis` (`tests/parity/re2j/build.gradle:87`) — by design, and seeds are logged/replayable via `-Pfuzz.one`. `bench-compare.py` and `gen-unicode.py` are stdlib-only (no venv/pinning needed — fine).
- **P2-8. Heap**: `-Xmx2g` required by unit (`tests/unit/build.gradle:23`), rebar (`tests/parity/rebar/build.gradle:42`), and fuzz JVMs; containers with <2 GB will OOM. Documented in comments, not in README's build section. Parallel-friendliness is fine (single `prepareVendor` instance; `testOnVm` `shouldRunAfter` test).

## Bottom line

The *correctness* gate is genuinely one command and survives a fresh clone today (verified). What stands between this repo and a defensible 1.0 freeze is everything around it: **no CI, no publish/sign/API-baseline machinery (self-acknowledged in TODO.md:18-20), a perf gate that self-passes on new machines, a tracked-but-"never-committed" non-reproducible oracle jar, and timing gates tuned to one laptop.** Freeze order I'd recommend: CI (even a single GitHub Actions `./gradlew check` on two OSes) → toolchain/`--release` fix → jar tracking decision → japicmp + publish dry-run — all before the version bump.
