## §1. P0 — freeze blockers

### P0-1. Nested counted repeats OOM the JVM before any budget fires — the README's central compile-contract sentence is false for this shape
`Tnfa.java:408-455` (`buildRepeat` desugars `{n}` as n re-builds), guarded only
by `MAX_REPEAT_COUNT = 1000` (`Parser.java:48`), which bounds **one** level.
Nesting multiplies. `Tnfa.Builder` has no meter, no cap; `WorkMeter`/state
caps exist only downstream in `TdfaCompiler`.

Reproduced on this tree:

| pattern (chars) | result |
|---|---|
| `(a{1000}){1000}` (15) | 1,002,001 TNFA states in 159 ms — accepted, no cap touched |
| `((a{300}){300}){300}` (19) | `OutOfMemoryError: Java heap space` in `Tnfa$Builder.buildRepeat` (−Xmx2g); 27 M states / ~2 s when it fits |

README:9: *"Patterns whose TDFA would exceed the determinization budget fail
compilation with a clean 'pattern too large' error rather than exhausting time
and memory."* An untrusted 19-char pattern raw-OOMs the process. The `Parser`
comment (44-47) shows the hazard was known at one level and the fix stopped
there. `CompileBudgetTest` covers `(a{1,100}){1,100}` — 4 orders of magnitude
below the bomb.
**Fix:** tick-count `Tnfa.Builder` state/edge creation (or a long-arithmetic
desugar-product check in `buildRepeat`, reject > ~10⁷) and throw the standard
budget rejection; the facade already translates that family to the clean PSE.

### P0-2. BYO-engine `matches()` accepts prefix matches as whole matches
`SingleCompile.java:128-129` — when artifacts are shared
(`!pikeCutMatters()`, the common case), `wholeEngine` returns **the custom find
engine**; `PatternCompiler.java:117` passes it as the whole engine. Its
`matchWhole` is the interface default `match(input, 0)` — an *unanchored
search*. `Matcher.matches()` (`core/Matcher.java:67-76`) only tests
`m != null`, and `ShellEmitter` (203-246) transcribes the same shape.

Reproduced (`Pattern.compile("a", 0, Wrap::new)` — engine without
`matchWhole` override):

```
BYO  matches("ab") = true      ← wrong
ASM  matches("ab") = false
VM   matches("ab") = false
```

Four doc comments promise the opposite (`PatternCompiler.java:110-116`,
`RegexEngineFactory.java:11-15`, `SingleCompile` class doc,
`SingleCompileWholeTest:152-153`). Every factory in the test suite is
`TdfaRunner::new` (which overrides `matchWhole`) — the hole is untested
by construction.
**Fix:** never hand the shared artifact to a foreign engine — shared case
returns `new TdfaRunner(a.whole)` (add a `nativeMatchWhole` flag/overload to
`wholeEngine`); fix the four comments; add the repro as a test with a
`matchWhole`-less engine.

### P0-3. `ParameterizedShortInputBench`'s `jur` lane measures our engine — the headline anchored table's `java.util.regex` row is fiction
`ParameterizedShortInputBench.java:6` imports `io.github.jemmix.tdfa.Pattern`;
the `jur` case (:63-66) is `Pattern.compile(regex)` + matcher-per-call — the
**asmc** engine in jur's calling idiom. No `java.util.regex` reference exists

Consequences: README §Headline's anchored `java.util.regex` row

conclusion are our-engine-vs-our-engine. The README's *search-side* jur claims
(0.94×/0.75×, "1.3× faster") come from `ShortFindBench` — correct lane,
committed artifact — and are unaffected. Residue of the same refactor:
`RegexEngine`/`RegexEngineFactory`/`MatchResult` imports now unused (:3-5).
**Fix:** qualify `java.util.regex.Pattern.compile` in the `jur` case, drop the
dead imports, re-capture §1, update README + BENCHMARKS.

### P0-4. README/BENCHMARKS rebar geomeans are not the committed artifacts' numbers — the docs flatter vs-re2j by ~22-26%
Committed artifacts (`results-rebar-{fast,accurate}.txt:351-352`):

## §2. P1 — should fix before freeze

### Correctness / contract

1. **Unmetered O(universe) case-fold scan at parse time** —
   `Parser.foldExpandRanges` (`Parser.java:397-416`) iterates every codepoint
   in a class under `(?i)`. Reproduced: 500 × `(?i)[\x{0}-\x{10FFFF}]` =
   3.6 s (~7 ms each, scaling linearly with pattern size) inside
   `Pattern.compile`, no cap, no error. Same pre-budget DoS class as P0-1.
   Fix: intersect the fold-orbit table with the range instead of scanning the
   universe, or meter it.
2. **Generated engines' `match(input, from)` skips the documented bounds
   check** — `TdfaAsmBackend.genMatch` String path (:441-474) vs
   `TdfaRunner.match` (:302-306). Reproduced: generated `a*` with
   `posFlagDeps()==0`: `.match("abc", 99)` returns a corrupt
   `MatchResult[start=99,end=99]` (or a wrong `null`), `-1` throws an
   incidental `StringIndexOutOfBoundsException` — both violate
   `RegexEngine.java:46-54`'s promised clean `IndexOutOfBoundsException`.
   Fix: emit a `from` bounds check delegating the polite throw (~12 bytes).
3. **BYO shell-emission fallback net misses `LinkageError`** —
   `PatternCompiler.java:126` catches only `RuntimeException`; the default
   path (:160) deliberately catches `RuntimeException | LinkageError` as the
   safety net for emitter bugs. A `VerifyError` on the BYO branch escapes
   `Pattern.compile` as a raw `Error`. One-token fix.
4. **Moore-minimization fixpoint is unmetered** — `DfaMinimizer.computePartition`
   (:173-199) ticks nothing and never receives the meter, while
   `WorkMeter.java:3-7` claims coverage of "every unbounded/fixpoint/quadratic
   loop in the pipeline". Near-cap literal-chain DFAs can peel one group per
   round ⇒ O(n²) sig builds, minutes, un-metered, inside `compile()`.
5. **ntag machinery is semantically inert; one comment asserts correctness
   flows through deleted code** — negative tags never enter histories
   (`TdfaCompiler.java:1222-1226`), so `Tnfa`'s ntag emission (:242-254,
   :320-330, :384-395) adds pass-through states for nothing, and
   `PikeSim.java:322` claims POSIX compare "sees ntags — via the utree path
   in the determinizer", removed 2026-09 (TdfaCompiler:1280-1284). Behavior
   is correct; the comments are freeze-rot that will mislead a thawed
   maintainer into "wiring up" the unreachable `SET_NIL` arms
   (`TdfaFinalVariants.java:57-61,163-165`). Fix comments; do **not** churn
   the NFA shape at freeze.
